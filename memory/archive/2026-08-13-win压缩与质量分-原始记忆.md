`D:\work\1_project\nas\video\` 下压缩/对比脚本的关键事实(2026-07-14 增强)。相关 [[local-tooling-yazi-psreadline]]。

**编码**:`batch_compress_structure.py` 用 digiKam 的 ffmpeg → `libx265 -crf 23 -preset veryfast`,音频 copy(失败回退 aac 128k)。CRF=恒定质量,**码率随内容动态浮动**(简单画面压得狠、复杂画面压得少),所以每个文件压缩率不同是正常的。想更省体积调高 CRF(26),别用固定码率。命令行 `--min-size/--min-bitrate` 只是"选哪些文件压"的筛选器,不是输出码率。

**质量评分坑(重要)**:
- digiKam 的 ffmpeg 是 `--disable-libvmaf`,**跑不了 VMAF**,只有 SSIM/PSNR(这俩滤镜在)。要 VMAF 得另装带 libvmaf 的 ffmpeg。
- 原片与压缩片**时基/帧率常不同**(iPhone 可变帧率、竖拍旋转元数据)。直接 ssim 会逐帧错位得到**假分数**(见过 0.87,实际 0.98)。必须:两路都 `fps=fps=<原片fps>,settb=AVTB` 归一,再用 `scale2ref` 把压缩片缩到原片实际尺寸(硬编码 scale 到编码尺寸会和自动旋转打架、导致分空白)。
- SSIM 评级:≥0.98 几乎无损 / 0.95~0.98 优 / 0.90~0.95 良 / <0.95 可见损失。完全相同(原样拷贝)→ SSIM 1.0、PSNR ∞。
- **ffmpeg 卡死坑**:子进程调 ffmpeg 必须加 `-nostdin`,否则个别文件会让 ffmpeg 等 stdin 输入而**永久挂起**(见过一个 4.5min 长片卡死,加 -nostdin 后 12s 出分)。质量评分单段超时设 240s,卡住自动杀掉跳过(记 None),不拖垮整批(2026-07-15)。
- **另一个坑**:任何一段(含整片)都必须用 `-t` 收在结尾前(GUARD 0.5s),有效时长取原/压两者较小值。否则可变帧率原片跑到结尾与恒定帧率压缩片总帧数不齐,触发 ffmpeg `scale2ref` 断言崩溃 `best_input>=0`→整片路径全 None 甚至硬崩(2026-07-15 修)。
- 实测家庭视频 CRF23 普遍 SSIM 0.97~0.99,旧的 KEEP_ORIGINAL 启发式(按码率降幅)偏保守,质量分能给客观证据翻案。
- 音频 `-c:a copy` 不动:AAC 已高效,只占总码率 ~2%,不值得压。

**抽样机制(重要)**:`--quality-sample N` 不是"截开头 N 秒",而是把 N 秒**拆成 `--quality-windows`(默认3)段,均匀撒在全片前/中/后再平均**——否则中段/后段才爆发的运动会漏测、分数偏乐观。`0`=整片(最准)。

**batch_compress_structure.py 结构(2026-07-14 重构)**:递归目标目录,只处理需压缩的视频(体积/码率达阈值),原件移入 `<root>/.old/`、压缩片放 `<root>/.new/`(前导点→资源管理器置顶,保留相对路径),其余原样留在原目录。默认压缩后自动出报告 `<root>/.report.csv` + `.report.xlsx`(对比 .old vs .new);`--no-report` 关,`--quality [--quality-sample N]` 加质量分。可配 `--old-dir/--new-dir` 改名。

**compare_compressed.py 输出**:CSV + xlsx(首行筛选+冻结) + summary.txt。列按"同属性 原/新 相邻"排;有 `综合建议`(结构化枚举,便于筛选:可删原版-质量优/良、保留原版-质量降/HDR、无收益-未压、待核对-码率降幅大 等)。`--quality` 才算分。
- yazi 菜单:`\ c` 对比(快)、`\ C` 对比+质量分(抽样30s)。Excel 需 openpyxl(已装)。
